# Sprinter Customer Care — setup

WhatsApp-styled customer-care app (the client's own **Sprinters** branding — not a
WhatsApp clone). Phone verification → OTP over WhatsApp → chat with an AI bot
(Claude) that hands off to a human admin.

Stack: Next.js 15 (App Router) · Supabase (Postgres/Auth/Realtime/Storage) ·
Anthropic (Claude) · Tailwind v4.

## 1. Install
```bash
npm install
cp .env.example .env.local   # already created; fill in values
```

## 2. Supabase
1. Create a project at supabase.com.
2. Run the schema: open **SQL Editor** and paste `supabase/migrations/0001_init.sql`
   (or `supabase db push` with the CLI). This creates tables, RLS, realtime, and the
   `chat-media` storage bucket.
3. Copy into `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Settings → API)
   - `SUPABASE_SERVICE_ROLE_KEY` (Settings → API, keep secret)
4. **Enable phone auth**: Authentication → Providers → Phone → enable. You do NOT
   need a real SMS provider because we deliver the code ourselves (next step).
5. **Send-SMS Auth Hook**: Authentication → Hooks → "Send SMS" → enable, point it at
   `https://YOUR_DEPLOY_URL/api/auth/otp-hook` (HTTP hook). Copy the generated secret
   into `SUPABASE_AUTH_HOOK_SECRET` (`v1,whsec_...`).
   - *Local dev:* use the Supabase CLI and set the hook URI in `supabase/config.toml`
     to `http://host.docker.internal:3000/api/auth/otp-hook`, or expose localhost with
     a tunnel. With `OTP_PROVIDER=mock` the code is printed to the Next server console,
     so you can test the whole flow without sending a real WhatsApp message.

## 3. Claude
- Set `ANTHROPIC_API_KEY`. `ANTHROPIC_MODEL` defaults to `claude-sonnet-5-5`.
- Tune the bot persona in `src/lib/ai/systemPrompt.ts`.

## 4. OTP delivery provider (provider-agnostic)
`OTP_PROVIDER` selects the WhatsApp sender in `src/lib/otp/sender.ts`:
- `mock` (default) — logs the code to the server console. Great for dev.
- `cloud_api` — WhatsApp Business Cloud API; set `WHATSAPP_PHONE_ID`,
  `WHATSAPP_TOKEN`, `WHATSAPP_TEMPLATE_NAME` (needs an approved auth template).
- `twilio` — set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_FROM`.

> The OTP is **our own** verification code generated by Supabase and delivered over
> WhatsApp — never a captured WhatsApp login code.

## 5. Make yourself an admin
Sign in once at `/verify` (creates your profile), then in Supabase SQL:
```sql
update public.profiles set is_admin = true where phone = '+9199XXXXXXXX';
```
Now `/admin` opens the support inbox.

## 6. Run
```bash
npm run dev     # http://localhost:3000
```

## Routes
- `/verify` — phone + OTP (Screen 1)
- `/chat` — user chat (Screen 2)
- `/admin` — admin login + inbox; `/admin/conversations/[id]` — live thread
